⇄ 无损传输 lossless-transfer

照片和视频传过去，
还是一模一样的字节。

一个零第三方依赖的传输工具：浏览器里拖拽上传、点选下载，分块 SHA-256 双向校验。 不重编码、不压缩、不缩放、不剥 EXIF —— 收到的字节与发出的字节完全一致。

查看源码 → 使用说明

为什么不一样

🔐 三处哈希必须一致

浏览器算一段、服务端独立再算一遍，最后整文件复核。三方都相同才标记 VERIFIED。

🧩 只搬字节，不解码

原图原视频直接搬运，分辨率、码率、色彩、EXIF、拍摄时间、容器格式原样保留。

📦 零第三方依赖

服务端只用 Python 标准库，前端是四个静态文件，连 SHA-256 都是自己实现的。

⏯️ 断点续传

传到一半关页面、断网都没关系，重新选同一个文件会从最后一块继续。

🌐 跨网络可用

配一条 SakuraFrp / frp 隧道即可跨公网使用，也能直接开原生 HTTPS。

🖼️ 预览不改原文件

缩略图取自相机写在 EXIF 里的那段，服务端不生成、不落盘任何派生图。

它怎么工作

浏览器切块算哈希

按 4 MiB 切片读原始字节，逐块算 SHA-256，同时滚动算出整文件哈希。

服务端独立复算

每块落盘前复算一次，整文件拼好后从头再算一次，任何一处不符立即中止。

两端哈希对上才成功

页面显示「✓ 已验证 · 字节完全一致」，并保留原始修改时间。

快速开始

# Windows：一条命令起 HTTPS 服务（自动生成自签证书）
pwsh -NoProfile -File .\scripts\start_web.ps1 -Open

# macOS / Linux：同一个服务，直接用 Python 标准库
python3 web_transfer.py --host 0.0.0.0 --port 8765 --dir ./shared --token 你的口令

启动后终端会打印访问地址与令牌，同一网络里用任意浏览器打开即可；跨网络再配一条 TCP 隧道。

⚠️

这个页面只是项目介绍。 GitHub Pages 只能托管静态文件，跑不了 Python 服务端 —— 真正的传输功能需要在你自己的电脑上启动 web_transfer.py（或那个 PowerShell 脚本）， 然后把隧道地址发给自己要传文件的人。所有文件都在你自己的机器上，不经过这里。
